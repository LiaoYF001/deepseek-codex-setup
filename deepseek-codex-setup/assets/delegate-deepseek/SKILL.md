# DeepSeek 委派

这是个人全局委派偏好，适用于当前任务的工作目录。自动发现本技能只授权评估和建议，不授权付费推理或向外部模型发送任务资料。

## 判断与征得同意

- 在上下文很长且能明确切分的文档、日志、代码提取/汇总，或规模足够的简单重复批处理任务中，主动考虑 DeepSeek。只有预期收益值得任务交接与复核成本时才建议；零碎小事直接完成，避免反复打扰。
- 用户明确要求“让 DeepSeek 做…”或给出包含任务的 `$broker` 调用，已授权该有界委派，直接执行，不重复确认。仅询问能力、讨论配置或调用本技能进行评估不等于授权执行。
- 隐式委派前，先形成具体建议：委派哪部分、需要读取或发送哪些资料/文件、预期交付、为什么适合、只读还是需要修改哪些文件及执行哪些命令。简短说明使用 DeepSeek API 计费，不猜测费用；用一个明确问题征求同意，等待答复后才发送任务资料或启动推理。
- 用户拒绝或尚未回答时不调用，可继续已获授权且不依赖该委派的本地工作。没有任务范围或收益的实质变化，不重复推销同一次委派。
- 一次同意覆盖该有界任务及同一子代理完成它所必需的补充上下文、普通命令和后续轮次，不逐步重复询问。新增独立委派或超出原范围时重新判断授权；启动状态不明时不要另开重复代理。

## 路线与交接

使用已安装的 `$mixagents-broker:broker` 技能，先读取其当前 `SKILL.md` 并遵循工作流。通过技能目录查找当前插件版本，不把缓存版本路径写死。

首次分派前调用 `mcp__broker__routes`，按实际结果选择 DeepSeek 路线及当前模型并向用户简述；不要硬编码模型或擅自切换路线配置。按 Broker 返回的后端使用对应调用方式，传入当前任务工作目录的绝对路径作为 `cwd`。不绑定安装时的目录，不改主代理的模型或服务商。

整理自包含任务，只交付完成它所需的上下文，不复制整段聊天，不在任务参数中提供密钥。长资料优先限定文件、章节、范围及输出格式，要求保留可复核的来源位置。

## 由主代理限定权限

- 每次分派默认 `read-only`。只有用户任务已授权修改、委派范围已包含修改且路线允许时，主代理才选择 `workspace-write`；路线的权限上限不等于每次任务的默认权限。
- 分派前由主代理明确批准可读输入、可写文件或子目录、可执行的命令类别及需要的验证。例如只允许修改指定源文件，并运行与改动有关的格式检查或测试；按任务需要选择验证，不强制所有任务运行测试。
- 告知子代理它与其他工作者共享目录，不覆盖或撤销他人改动；并发写入使用不重叠的文件责任范围，必要时先隔离工作区。要求它在需要额外写入、命令或权限时暂停并报告。
- 主代理可批准原用户任务及已同意委派范围内的普通读取、修改和命令；此偏好不自动授权破坏性操作、范围外修改、发布/推送、秘密访问或其他外部行动。
- 这些限制由主代理任务约定与 Codex 沙箱共同提供，不能声称主代理会在技术上拦截并审批每条命令。Broker App Server 的运行时 `on-request` 审批由宿主转交用户，不能伪造主代理批准来替代，也不能修改插件以绕过审批。
- 新工作目录需要宿主授权时使用 Broker 正常流程；不把允许根目录扩大到整个用户目录或磁盘。用户拒绝/取消后，没有新指示不重试。

## 跟进与验收

按 Broker 技能管理子代理；运行期间继续可独立推进的工作，在需要结果时等待。主代理检查实际输出及改动差异，结合任务风险核验来源、范围和结果；子代理自述成功不足以证明完成。发现越界需求先收回控制并评估已有授权，不能默许扩大范围。

向用户汇报委派结果、复核结论和未解决事项。模型更新检查仍使用 `$check-deepseek-models`，保持“默认只检查、明确指定后切换”；本技能不创建定时检查或后台自动委派。
