# DeepSeek 委派

这是个人全局委派偏好，适用于当前任务及其所需的具体目录。自动发现本技能只授权评估和建议，不授权付费推理或向外部模型发送任务资料。

## 判断与征得同意

- 在上下文很长且能明确切分的文档、日志、代码提取/汇总，或规模足够的简单重复批处理任务中，主动考虑 DeepSeek。只有预期收益值得任务交接与复核成本时才建议；零碎小事直接完成，避免反复打扰。
- 用户明确要求“让 DeepSeek 做…”或给出包含任务的 `$broker` 调用，已授权该有界委派，直接执行，不重复确认。仅询问能力、讨论配置或调用本技能进行评估不等于授权执行。
- 隐式委派前，先形成具体建议：委派哪部分、需要读取或发送哪些资料/文件、预期交付、为什么适合、只读还是需要修改哪些文件及执行哪些命令。简短说明使用 DeepSeek API 计费，不猜测费用；用一个明确问题征求同意，等待答复后才发送任务资料或启动推理。
- 用户拒绝或尚未回答时不调用，可继续已获授权且不依赖该委派的本地工作。没有任务范围或收益的实质变化，不重复推销同一次委派。
- 一次同意覆盖该有界任务及同一子代理完成它所必需的补充上下文、普通命令和后续轮次，不逐步重复询问。新增独立委派或超出原范围时重新判断授权；启动状态不明时不要另开重复代理。

## 路线与交接

使用已安装的 `$mixagents-broker:broker` 技能，先读取其当前 `SKILL.md` 并遵循工作流。通过技能目录查找当前插件版本，不把缓存版本路径写死。

取得有界委派同意后，先完成下方目录预授权，再首次调用 Broker 的 `routes`、`list_agents` 或 `spawn`。随后按 `mcp__broker__routes` 的实际结果选择 DeepSeek 路线及当前模型并向用户简述；不要硬编码模型或擅自切换路线配置。按 Broker 返回的后端使用对应调用方式，每次 `spawn.cwd` 使用对应子任务真实工作目录那次预检查返回的规范化 `root`，不误用最后一次检查的其他目录。不绑定安装时的目录，不改主代理的模型或服务商。

整理自包含任务，只交付完成它所需的上下文，不复制整段聊天，不在任务参数中提供密钥。长资料优先限定文件、章节、范围及输出格式，要求保留可复核的来源位置。

## 由主代理限定权限

- 用户已给予全局目录授权偏好：“只要你有权限的目录，你都可以授权给 DeepSeek。”在已同意的有界委派中，主代理可将完成任务所需、且自身已有文件系统访问权限的具体子任务工作目录预授权给 Broker，无需再问一次目录权限；它可以位于主代理当前 `cwd` 之外。它不授权尚未同意的推理、发送额外资料、扩大任务范围或提高沙箱权限，也不自动授予子代理修改权限。
- 每次分派默认 `read-only`。只有用户任务已授权修改、委派范围已包含修改且路线允许时，主代理才选择 `workspace-write`；路线的权限上限不等于每次任务的默认权限。
- 分派前由主代理明确批准可读输入、可写文件或子目录、可执行的命令类别及需要的验证。例如只允许修改指定源文件，并运行与改动有关的格式检查或测试；按任务需要选择验证，不强制所有任务运行测试。
- 告知子代理它与其他工作者共享目录，不覆盖或撤销他人改动；并发写入使用不重叠的文件责任范围，必要时先隔离工作区。要求它在需要额外写入、命令或权限时暂停并报告。
- 主代理可批准原用户任务及已同意委派范围内的普通读取、修改和命令；此偏好不自动授权破坏性操作、范围外修改、发布/推送、秘密访问或其他外部行动。
- 这些限制由主代理任务约定与 Codex 沙箱共同提供，不能声称主代理会在技术上拦截并审批每条命令。Broker App Server 的运行时 `on-request` 审批由宿主转交用户，不能伪造主代理批准来替代，也不能修改插件以绕过审批。

## 目录预授权与连接状态

在本任务首次调用 Broker 的 `routes`、`list_agents` 或 `spawn` **之前**，使用 PowerShell 7.2+ 运行本技能的 [scripts/ensure_workspace.ps1](scripts/ensure_workspace.ps1)：

```powershell
pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass -File '<本技能目录>/scripts/ensure_workspace.ps1' -WorkspacePath '<已批准的具体绝对目录>'
```

- 对每个实际要启动的子任务 `cwd` 分别运行一次，保存目录与返回 `root` 的对应关系；每次 `spawn.cwd` 使用该子任务自己的结果。已知必要目录预检查须在首次 Broker 调用前完成，后续新增子任务目录也须在启动前预检查。`-ExecutionPolicy Bypass` 只影响此次 PowerShell 进程，不修改系统策略或文件访问权限。
- `workspaceRoots` 只控制 Broker 允许在哪个 `cwd` 启动，不会传入 App Server 作为跨目录读写授权，也不是可读取文件的边界；只读沙箱可能读取根目录外的文件。主代理仍须明确每个子任务的输入、输出和命令范围。若任务确需在其他目录修改，仅在已授权的有界委派范围内确有必要时，以该目录为真实 `cwd` 分派子任务，避免重复推理；路线或沙箱不能支持的部分由主代理执行，不扩大权限。
- 脚本只把必要的精确目录合并到配置的顶层 `workspaceRoots`，保留原有根目录及其他配置；已被可核验的相同目录或祖先目录覆盖时不写入。默认配置为 `%APPDATA%/MixAgents/broker.json`，存在 `MIXAGENTS_BROKER_CONFIG` 时遵循它；`-ConfigPath` 仅用于显式指定的配置或隔离测试。不要输出配置内容、凭据或环境映射，也不要调用模型测试此步骤。
- 脚本核验新增目录可访问并解析 Windows 目录别名；拒绝通配符、无效/无法访问的新增路径，以及把磁盘根目录、用户主目录或其祖先作为自动新增目录。已有根目录字符串格式无效时报错；已删除或无法访问的旧根目录原样保留，不视为覆盖证据，也不阻塞无关新目录的授权。不要通过扩大根目录、提权、修改插件或终止无关进程解决失败。
- 成功输出小型 JSON：`changed`、规范化的 `root`、`config`、原始文件 `backup` 和 `reconnectRequired`。写入使用跨进程锁、写前冲突检查、原子替换及同目录备份；失败只输出固定 `error`。遇到错误先处理该具体原因，不继续启动子代理。
- Broker 连接可能缓存配置。`reconnectRequired: true` 时，已有连接须通过受支持的重新连接流程或新任务加载配置后才继续；`false` 也不证明现有连接已加载近期由别处修改的配置。没有可用的受支持重新连接方式时，说明需要新任务加载，不强行刷新或反复 `spawn`。
- 出现 `workspace_approval_declined` 时停止本次重试。只有已有明确授权的具体修复完成，且新的连接/任务或其他可核验的新状态解决了原阻塞，才继续一次验证；重复失败停止。用户明确拒绝或取消则停止，不能把此全局偏好当作对拒绝的覆盖。运行时 `on-request` 审批始终由宿主处理。

## Windows 普通命令执行

- Windows 上的 Broker 独立运行目录不会自动继承主 Codex 的沙箱设置。已采用配套修复的机器通过用户级 `broker.json.codexBin` 指向个人工具目录中的 `broker-codex.cmd`，为工作进程启用官方 `unelevated` 沙箱；保留主 Codex 的设置、Broker 的独立配置目录、`on-request` 和本次 `access`。安装或更新启动器后须让新连接加载，不能以配置文件已修改推断旧连接已生效。
- 若普通读取也返回 `CreateProcess ... Rejected` 或 `rejected by user`，立即停止重复执行，核对启动器、连接状态和宿主日志。该文案本身不能证明用户点击了拒绝；宿主也可能自动拒绝无法处理的审批。只有具体修复完成并有可核验的新状态后，才继续一次已批准的验证；再次失败就报告。
- 不以完整访问、自动接受审批、复制主 Codex 沙箱凭据或改写插件缓存解决故障。`unelevated` 仍受沙箱和任务范围限制，不保证额外权限、网络或发布操作可以通过。用户真实拒绝或取消时必须停止；需要主代理完成的部分在原任务授权内接手。

## 跟进与验收

按 Broker 技能管理子代理；运行期间继续可独立推进的工作，在需要结果时等待。主代理检查实际输出及改动差异，结合任务风险核验来源、范围和结果；子代理自述成功不足以证明完成。发现越界需求先收回控制并评估已有授权，不能默许扩大范围。

向用户汇报委派结果、复核结论和未解决事项。模型更新检查仍使用 `$check-deepseek-models`，保持“默认只检查、明确指定后切换”；本技能不创建定时检查或后台自动委派。
