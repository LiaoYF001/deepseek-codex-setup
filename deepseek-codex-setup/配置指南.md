# Codex + DeepSeek 子代理：Windows 全局配置指南

更新日期：2026-09-15；配置包修订版 `2026.09.15`。

本版加入目录授权和 Windows 命令审批故障修复、调用前目录检查及旧安装升级步骤。已经按 2026-09-12 版安装的机器可直接看第 6.4–6.5 节，无需重新导入密钥或更换模型。

本文记录本次实际完成的配置，并提供可复制到其他 Windows 机器的个人技能与规则。按顺序完成配置后，同一 Windows 用户的不同 Codex 项目和任务都可以使用 DeepSeek 子代理；每次使用当前任务的目录。

配套文件不含 API Key、原机器的账户信息、Codex 登录文件、配置备份或聊天记录。新机器必须使用自己的本机凭据配置。

## 1. 最终效果与适用范围

| 项目 | 本文配置 |
| --- | --- |
| 主代理 | 保持目标机器现有的模型、服务商和登录方式 |
| DeepSeek 接口 | 官方 `https://api.deepseek.com`，Responses 协议 |
| 默认 API 模型名 | `deepseek-flash`；2026-09-12 核对时对应 DeepSeek V4.1-Flash，本次修复未重新核验别名版本 |
| 子代理上下文 | 1,000,000 tokens |
| 调用方式 | MixAgents Broker 插件，当前采用 `app_server` 后端 |
| 可用范围 | 本机同一用户的所有 Codex 任务；目录权限仍按具体任务处理 |
| 文件权限 | 路线上限为 `workspace-write`；每次分派仍默认 `read-only` |
| Windows 执行后端 | Broker 专用启动器为独立工作进程启用 `unelevated` 沙箱；主 Codex 原有沙箱设置保留 |
| 主动委派 | 主代理发现合适工作后提出具体建议，得到用户同意再调用 |
| 明确指示 | 用户明确说使用 DeepSeek，或给出包含任务的 `$broker` 指令，即可按该范围调用 |
| 目录授权 | 用户同意委派后，主代理可直接登记任务所需且自身有权访问的具体启动目录，无需逐目录再次询问 |
| 模型更新 | `$check-deepseek-models` 默认只检查并列出候选，用户明确选择后才切换 |
| 自动化 | 不创建定时检查，不在后台自动发起付费委派 |

调用链：

```text
用户任务 → 主代理整理有界子任务并确认调用授权
         → 目录预检查（首次 Broker 工具调用前）→ Broker 本地 MCP 服务
         → 独立 Codex App Server 工作代理 → DeepSeek 官方 API
         ← 主代理复核输出、文件差异和必要验证 ← 返回执行结果
```

主代理只传递完成子任务需要的材料，不会自动复制整个父对话。被读取的相关文件和工具输出可能发送给 DeepSeek。工作代理在指定目录工作，Broker 本身不自动建立 worktree 或合并改动。

**版本边界：** 原 `codex-deepseek-subagent` 安装链接已经变成兼容入口。Codex **0.149.0 及以上**应使用 Broker；旧的独立 agent TOML、`SubagentStart` Hook 安装流程仅保留给兼容旧版本。不要在当前版本照抄旧方案，也不要为此降级 Codex。

初次安装验证环境为 Codex **0.153.4**、Broker **0.1.1**、Node **24.19.0**、npm **11.17.0**。本次目录授权修复验证环境为 Codex **0.154.0-alpha.6.2**、桌面版 **26.908.4834.0**、Broker **0.1.1**。Broker 文档最低要求 Node **22.19.0**。这些是验证记录，不代表所有未来版本已经测试过。复现时核对上游说明和实际安装版本。

本文及配套检查脚本面向 Windows，要求 **PowerShell 7.2 或更新版本，推荐 7.4 或更新版本**。WSL、远程主机、另一 Windows 用户以及 macOS/Linux 的凭据和技能目录是独立环境，不能假定复制 Windows 用户配置后自动生效。

### 2.2 检查依赖并确定路径

先安装并正常登录目标机器的 Codex。在 **PowerShell 7.2 或更新版本**中运行；以下命令应能找到相应程序：

```powershell
$PSVersionTable.PSVersion
if ($PSVersionTable.PSVersion -lt [version]'7.2') {
    throw '请使用 PowerShell 7.2 或更新版本，推荐 7.4 或更新版本。'
}
codex --version
node --version
npm.cmd --version
git --version
```

如果普通终端找不到 Codex，先尝试 Codex 内的终端，或找到目标机器实际的 Codex 可执行文件后使用其完整路径。不要复制原机器带版本号的程序路径。`Get-Command codex`、`Get-Command node` 可查看本机解析到的位置。

确认 Node ≥ 22.19.0，且 PowerShell ≥ 7.2（推荐 ≥ 7.4）。缺少 Node/npm 时可安装 [Node.js 官方 LTS](https://nodejs.org/en/download)，然后重新打开终端和 Codex。**Node 必须能被未来启动 Codex 的环境找到**；仅在一次终端会话临时设置 PATH 不保证其他启动方式也能找到它。

将配置包解压，进入包含 `配置指南.md` 和 `assets` 的目录，然后运行：

```powershell
$ErrorActionPreference = 'Stop'
$bundleDir = (Get-Location).Path
if (-not (Test-Path -LiteralPath (Join-Path $bundleDir 'assets\broker.example.json'))) {
    throw '请先进入解压后的 deepseek-codex-setup 目录。'
}
$cxDir = if ($env:CODEX_HOME) { $env:CODEX_HOME } else {
    Join-Path $env:USERPROFILE '.codex'
}
$mixDir = Join-Path $env:APPDATA 'MixAgents'
$backupStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
New-Item -ItemType Directory -Path $cxDir -Force | Out-Null
New-Item -ItemType Directory -Path $mixDir -Force | Out-Null
```

尊重已经设置的 `CODEX_HOME`，不要为安装切换它。后文的“个人配置”均指该目录，而不是当前项目下的 `.codex`。

### 2.3 可选：像本次一样，仅补齐便携版 npm

本次 Codex 已提供 Node，但没有 `npm.cmd`。采用了官方 Node 24.19.0 便携包，并校验 SHA-256。目标机器已经有合适的 Node/npm 时跳过本节。

```powershell
$nodeVersion = '24.19.0'
$nodeArch = switch ([Runtime.InteropServices.RuntimeInformation]::OSArchitecture.ToString()) {
    'X64' { 'x64' }
    'Arm64' { 'arm64' }
    default { throw '本示例只处理 Windows x64 或 ARM64。' }
}
$nodeFolder = "node-v$nodeVersion-win-$nodeArch"
$nodeZipName = "$nodeFolder.zip"
$nodeBaseUrl = "https://nodejs.org/dist/v$nodeVersion/"
$nodeTools = Join-Path $cxDir 'tools'
$nodeDir = Join-Path $nodeTools $nodeFolder

if (-not (Test-Path -LiteralPath (Join-Path $nodeDir 'npm.cmd'))) {
    if (Test-Path -LiteralPath $nodeDir) {
        throw '目标便携目录已经存在但缺少 npm；请先检查，避免覆盖。'
    }
    $nodeZipPath = Join-Path $env:TEMP ("$nodeFolder-" + [guid]::NewGuid().ToString('N') + '.zip')
    $checksums = Invoke-RestMethod -Uri ($nodeBaseUrl + 'SHASUMS256.txt')
    $matchedLine = @($checksums -split "`n" | Where-Object {
        $_ -match ('\s' + [regex]::Escape($nodeZipName) + '\s*$')
    })
    if ($matchedLine.Count -ne 1) { throw '未找到唯一的官方校验值。' }
    $expectedHash = ($matchedLine[0].Trim() -split '\s+')[0]
    Invoke-WebRequest -Uri ($nodeBaseUrl + $nodeZipName) -OutFile $nodeZipPath
    if ((Get-FileHash -LiteralPath $nodeZipPath -Algorithm SHA256).Hash -ne $expectedHash) {
        throw '压缩包校验失败；停止安装。'
    }
    New-Item -ItemType Directory -Path $nodeTools -Force | Out-Null
    Expand-Archive -LiteralPath $nodeZipPath -DestinationPath $nodeTools
}
$env:PATH = $nodeDir + ';' + $env:PATH
& (Join-Path $nodeDir 'node.exe') --version
& (Join-Path $nodeDir 'npm.cmd') --version
```

这段代码只更新当前 PowerShell 的 PATH，适合已有可用 Node、仅安装插件时缺 npm 的情况。若决定让便携 Node 也成为新机器的长期运行环境，应把 `$nodeDir` 加入该用户 PATH，并在完全重启后重新验证 `node` 和 `npm.cmd`；不要改写系统 PATH 或删除原有条目。

## 4. 配置全局 DeepSeek 路线与权限

默认配置位置为 `%APPDATA%\MixAgents\broker.json`。如果本来就使用 `MIXAGENTS_BROKER_CONFIG`，该值必须为绝对路径，改用它所指向的文件，保持 Codex 和检查技能读取同一份配置。

目标文件不存在时，可以直接复制模板：

```powershell
$brokerConfig = if ($env:MIXAGENTS_BROKER_CONFIG) {
    if (-not [IO.Path]::IsPathFullyQualified($env:MIXAGENTS_BROKER_CONFIG)) {
        throw 'MIXAGENTS_BROKER_CONFIG 必须是绝对路径。'
    }
    $env:MIXAGENTS_BROKER_CONFIG
} else {
    Join-Path $mixDir 'broker.json'
}
if (Test-Path -LiteralPath $brokerConfig) {
    throw '已有 Broker 配置；请先备份并手动合并路线，不要直接覆盖。'
}
New-Item -ItemType Directory -Path (Split-Path -Parent $brokerConfig) -Force | Out-Null
Copy-Item -LiteralPath (Join-Path $bundleDir 'assets\broker.example.json') -Destination $brokerConfig
```

完整模板如下，**没有 API Key**：

```json
{
  "defaultRoute": "deepseek-flash",
  "workspaceRoots": [],
  "routes": {
    "deepseek-flash": {
      "description": "DeepSeek 官方 Flash 子代理；默认只读，可由主代理在用户批准的任务范围内授权工作区写入及命令执行。",
      "provider": "deepseek",
      "providerName": "DeepSeek",
      "model": "deepseek-flash",
      "contextWindow": 1000000,
      "baseUrl": "https://api.deepseek.com",
      "envKey": "DEEPSEEK_API_KEY",
      "maxAccess": "workspace-write"
    }
  }
}
```

已有路线时保留所有其他路线和无关字段，只增加或更新目标 DeepSeek 路线。`defaultRoute` 是默认选择，按照需要明确设置，不覆盖已有用途不同的同名路线。省略 `reasoningEffort` 是本方案的有意选择；不要机械复制 OpenCode 示例中的 `medium`。

**权限分两层：** `maxAccess` 是上限；每次调用不传 `access` 时仍默认只读。只有用户已经授权修改、主代理批准了具体范围时，才分派 `workspace-write`。命令能否执行同时受任务约定、沙箱及宿主审批约束，不能仅根据这个上限推断。

模板的 `workspaceRoots` 初始为空，不绑定安装目录。在具体任务已获得委派同意后，主代理通过第 6.3 节辅助脚本登记必要的精确启动目录。此步骤必须早于该连接首次调用 Broker 工具，包括 `routes` 和 `list_agents`；这两项只读工具也会触发配置缓存。

`workspaceRoots` 只验证某目录是否可以作为子代理的启动 `cwd`，不是实际读写沙箱的根列表，也不是读取范围保证。登记 A、B 两个目录后，以 A 启动的子代理不会因此自动获得 B 的写权限。任务确需修改 B 时，在已批准范围内以 B 为工作目录分派对应有界子任务，或由主代理完成该部分；不要仅增加配置根就声称跨目录写入已可用。全局可用不等于所有目录预先开放。

## 5. 配置 API Key 与凭据隔离

### 5.1 先设置主代理的环境过滤

在个人 `$cxDir\config.toml` 合并下面的表。已有该表时只增加这一项，不重复声明同名表：

```toml
[shell_environment_policy.filters]
MIXAGENTS_BROKER_CREDENTIALS_JSON = "exclude"
```

这是当前推荐的过滤写法。若目标配置已经使用旧式 `shell_environment_policy.exclude` 或 `include_only`，同一配置层不要与 `filters` 混用：可以在原 `exclude` 列表增加该变量名，或在理解现有规则后等价迁移全部规则。保留其他过滤项及 `shell_environment_policy.set`；不要把凭据映射写入 `set`。

这个过滤针对模型生成的 shell 命令。Broker 插件仍需要从启动 Codex 的进程环境获取凭据映射。不要把凭据内容放进 TOML、Broker JSON、技能正文或对话。

### 5.2 在目标机器本地导入凭据

本次原始配置曾从单行文本读取密钥；下面提供可直接复现、且不会把密钥写入命令历史的掩码输入方式。在目标 Windows 用户自己的 PowerShell 7.2 或更新版本中执行：

```powershell
$ErrorActionPreference = 'Stop'
$secureInput = $null
$secretPointer = [IntPtr]::Zero
$apiKey = $null
$existingCredentialJson = $null
$credentialMap = $null
$newCredentialJson = $null
try {
    $secureInput = Read-Host '输入此机器使用的 DeepSeek API Key' -AsSecureString
    $secretPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureInput)
    $apiKey = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($secretPointer).Trim()
    if ([string]::IsNullOrWhiteSpace($apiKey)) { throw 'Empty key' }

    $existingCredentialJson = [Environment]::GetEnvironmentVariable('MIXAGENTS_BROKER_CREDENTIALS_JSON', 'User')
    $credentialMap = if ($existingCredentialJson) {
        ConvertFrom-Json -InputObject $existingCredentialJson -AsHashtable
    } else { @{} }
    if ($credentialMap -isnot [Collections.IDictionary]) { throw 'Invalid credential map' }
    $credentialMap['DEEPSEEK_API_KEY'] = $apiKey
    $newCredentialJson = ConvertTo-Json -InputObject $credentialMap -Compress
    [Environment]::SetEnvironmentVariable('MIXAGENTS_BROKER_CREDENTIALS_JSON', $newCredentialJson, 'User')

    $credentialDirectory = Join-Path $env:APPDATA 'MixAgents'
    New-Item -ItemType Directory -Path $credentialDirectory -Force | Out-Null
    $ownerBinding = @{ ownerSid = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value }
    $ownerBinding | ConvertTo-Json | Set-Content -LiteralPath (Join-Path $credentialDirectory 'credential-owner.json') -Encoding utf8NoBOM
    Write-Host '用户级凭据及本机身份绑定已保存；请完全退出并重新打开 Codex。'
} catch {
    Write-Error '凭据导入未完成。请检查输入、现有映射格式和用户目录权限；不要将原始错误或密钥粘贴到聊天。'
} finally {
    if ($secretPointer -ne [IntPtr]::Zero) {
        [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($secretPointer)
    }
    if ($null -ne $secureInput) { $secureInput.Dispose() }
    if ($null -ne $credentialMap) { $credentialMap.Clear() }
    $apiKey = $null
    $existingCredentialJson = $null
    $newCredentialJson = $null
}
```

如果选择文本导入，在上面 `try` 内将输入密钥的三行（`Read-Host -AsSecureString`、`SecureStringToBSTR`、`PtrToStringBSTR`）替换为下面代码，保留后续空值检查及其余部分；文本文件只保存密钥，不要包含说明文字，也不要放入本配置包：

```powershell
$localKeyPath = Read-Host '本机密钥文本文件的绝对路径'
if (-not [IO.Path]::IsPathFullyQualified($localKeyPath)) { throw '需要绝对路径。' }
$apiKey = [IO.File]::ReadAllText($localKeyPath).Trim()
```

不得通过聊天、命令参数或输出完整环境变量来传递密钥。仅设置裸 `DEEPSEEK_API_KEY` 不能保证它穿过插件边界；本方案使用名为 `MIXAGENTS_BROKER_CREDENTIALS_JSON` 的映射，里面的键才是 `DEEPSEEK_API_KEY`。

`credential-owner.json` 只保存当前用户 SID，是配套检查脚本的身份绑定，**必须在每台目标机器重新生成，不能从旧机复制**。便携脚本通过 Windows SID 解析验证格式，再与运行身份比较。用户环境变量是本机存储方式，不是加密保险库；本方案通过不回显和 shell 过滤减少密钥进入模型上下文的机会。

## 6. 安装两项个人技能与主动委派规则

### 6.1 安装技能

在之前初始化路径的 PowerShell 会话中执行。两个目标目录都不存在时才复制；存在时先检查身份与差异、备份到技能目录之外，再决定更新，不能覆盖用途不同的个人技能。

```powershell
$personalSkillDir = Join-Path $cxDir 'skills'
$skillNames = @('check-deepseek-models', 'delegate-deepseek')
foreach ($skillName in $skillNames) {
    if (Test-Path -LiteralPath (Join-Path $personalSkillDir $skillName)) {
        throw "个人技能 $skillName 已存在；请先检查并备份，避免直接覆盖。"
    }
}
New-Item -ItemType Directory -Path $personalSkillDir -Force | Out-Null
foreach ($skillName in $skillNames) {
    $skillSource = Join-Path (Join-Path $bundleDir 'assets') $skillName
    Copy-Item -LiteralPath $skillSource -Destination (Join-Path $personalSkillDir $skillName) -Recurse
}
```

复制整个技能目录，包括 `agents/openai.yaml` 和脚本，不要只复制 `SKILL.md`。

`check-deepseek-models` 根据官方当前模型表、更新记录、Responses 文档和账号可用模型做比较。`GET /models` 只证明可见的模型 ID，不能单独证明发布日期、稳定版状态或协议兼容。展示名称与 API 名称也不能自行互相拼写替换。

`delegate-deepseek` 让主代理在适合时主动建议：长资料提取/汇总、规模足够的重复批处理等。建议应说明范围、材料、交付、收益及读写权限，等用户同意后才发起推理。小任务直接处理；用户拒绝或未答复时不调用。明确指定 DeepSeek，以及已批准子任务内的必要继续执行，不反复请求同一授权。

### 6.2 写入个人 AGENTS.md

打开 `$cxDir\AGENTS.md`，将配套 [assets/AGENTS.deepseek.md](assets/AGENTS.deepseek.md) 的完整内容合并进去；文件不存在时可以新建 UTF-8 文本。

保留已有规则。如果已经存在下面这对标记，只更新标记内部对应块，确保只有一份，不要反复追加：

```text
<!-- BEGIN personal-deepseek-delegation -->
...
<!-- END personal-deepseek-delegation -->
```

个人 AGENTS 块只负责始终可见的偏好和技能入口；详细委派流程留在个人技能中。不要直接编辑插件缓存里的 Broker 技能，插件升级可能覆盖它。

主代理在委派前批准具体可读输入、可写文件或子目录、命令类别和必要验证。DeepSeek 遇到范围外操作先报告，主代理检查实际输出与改动。这是任务约定加 Codex 沙箱，**不是主代理在技术上逐条拦截所有命令**。Broker 的 `on-request` 运行时审批仍由宿主呈现给用户，不能以“主代理批准”伪造或绕过。

### 6.3 任务目录预检查

本配置的个人规则允许：**用户同意具体委派后，主代理可以直接授权自身已有访问权限、且该任务确实需要的启动目录，不再逐目录询问。** 此偏好不授权尚未同意的推理，也不扩大任务或文件读写范围。

技能会在首次 Broker 工具调用前运行以下步骤。需要手动修复或验证时，在 PowerShell 7.2+ 中执行：

```powershell
$cxDir = if ($env:CODEX_HOME) { $env:CODEX_HOME } else {
    Join-Path $env:USERPROFILE '.codex'
}
$workspaceChecker = Join-Path $cxDir 'skills\delegate-deepseek\scripts\ensure_workspace.ps1'
$approvedWorkspace = Read-Host '输入已批准子任务的具体工作目录（绝对路径）'
$preflightJson = & pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass -File $workspaceChecker -WorkspacePath $approvedWorkspace
if ($LASTEXITCODE -ne 0) { throw '目录预检查失败；处理所报原因后再调用 Broker。' }
$preflight = $preflightJson | ConvertFrom-Json
$preflight
```

脚本遵循 `MIXAGENTS_BROKER_CONFIG`，否则使用 `%APPDATA%\MixAgents\broker.json`。仅用于明确的配置路径或隔离测试时可传 `-ConfigPath`。首次安装必须先按第 4 节创建有效配置；脚本不生成模型路线。

- 新增目录必须是存在且可访问的绝对路径，不接受通配符；脚本会解析 Windows 目录别名，并拒绝自动新增磁盘根、用户主目录及其祖先。
- 未被现有目录根覆盖时，仅合并该精确目录；保留其他配置，使用并发锁、写前冲突检查和原子替换，原始备份保存在配置旁。
- 已被相同或祖先目录覆盖时不写入；已删除或无法访问的旧根原样保留，不作为覆盖证据；格式无效的旧根会报错并保持配置不变。
- 成功结果包括 `changed`、规范化 `root`、`config`、`backup`、`reconnectRequired`；失败输出固定错误代码。脚本不读密钥、不请求模型。
- 每次 `spawn.cwd` 使用该子任务预检查返回的 `root`；存在多个子任务目录时分别检查并保留对应关系，不能误用最后一个结果。

**连接缓存：** Broker 0.1.1 在首次工具调用时加载配置。尚未调用过任何 Broker 工具的新连接可以在预检查后继续；已缓存旧配置的连接必须正常重连，或完全重启 Codex 后创建新任务。`reconnectRequired: true` 提示配置已写入；`false` 只表示这次没写，不能证明旧连接已刷新。不要反复启动子代理来碰运气，也不要终止无关进程或修改插件来绕过宿主审批。

### 6.4 从旧配置包升级

已安装 2026-09-12 版且模型、凭据正常时，只需升级个人委派技能、对应 AGENTS 块及必要目录。保留现有模型检查技能、密钥、路线和其他插件。

1. 解压新版，进入包含本指南和 `assets` 的目录。核对目标是同名个人委派技能；若曾自行修改，先比较差异再合并。
2. 在技能目录之外备份旧委派技能；复制新版整个目录，包括新增脚本。下面代码适用于未自行定制的旧版；它保留目标目录中的其他文件。

```powershell
$ErrorActionPreference = 'Stop'
$bundleDir = (Get-Location).Path
$cxDir = if ($env:CODEX_HOME) { $env:CODEX_HOME } else {
    Join-Path $env:USERPROFILE '.codex'
}
$upgradeSource = Join-Path $bundleDir 'assets\delegate-deepseek'
$upgradeTarget = Join-Path $cxDir 'skills\delegate-deepseek'
if (-not (Test-Path -LiteralPath (Join-Path $upgradeSource 'scripts\ensure_workspace.ps1'))) {
    throw '请进入新版配置包目录。'
}
if (-not (Test-Path -LiteralPath (Join-Path $upgradeTarget 'SKILL.md'))) {
    throw '未发现旧委派技能；首次安装请使用第 6.1 节。'
}
$upgradeBackup = Join-Path $cxDir ('backups\deepseek-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $upgradeBackup | Out-Null
Copy-Item -LiteralPath $upgradeTarget -Destination $upgradeBackup -Recurse
$personalAgents = Join-Path $cxDir 'AGENTS.md'
if (Test-Path -LiteralPath $personalAgents) {
    Copy-Item -LiteralPath $personalAgents -Destination (Join-Path $upgradeBackup 'AGENTS.md')
}
foreach ($entry in Get-ChildItem -LiteralPath $upgradeSource) {
    Copy-Item -LiteralPath $entry.FullName -Destination $upgradeTarget -Recurse -Force
}
foreach ($relativeFile in @('SKILL.md', 'scripts\ensure_workspace.ps1')) {
    $copiedFile = Join-Path $upgradeTarget $relativeFile
    if (-not (Test-Path -LiteralPath $copiedFile) -or
        (Get-FileHash -LiteralPath $copiedFile).Hash -ne (Get-FileHash -LiteralPath (Join-Path $upgradeSource $relativeFile)).Hash) {
        throw '升级后文件校验失败；请检查备份和复制结果，暂不启动 Broker。'
    }
}
```

3. 按第 6.2 节用新版 `assets/AGENTS.deepseek.md` 替换原标记块，保留其他内容，确保起止标记各一份。
4. 按第 6.3 节为已批准的实际子任务目录运行预检查。已有 `workspaceRoots` 不覆盖，其他路线不变。配置存在问题时先修复，不复制模板覆盖整份配置。
5. 按第 6.5 节安装 Broker 专用 Windows 启动器，再完整退出并重启 Codex，按第 7 节检查。升级本身不需要重新输入 API Key、更换模型或自动进行付费推理。

### 6.5 修复 Broker 独立进程的 Windows 沙箱

Broker 0.1.1 每次启动都会重新生成独立 Codex 配置，但没有继承主 Codex 的 Windows 沙箱设置。该版本 Codex 在 Windows 沙箱未启用、同时要求只读或工作区写入限制时，连普通 `Get-Content` 都会请求批准。如果审批通过 `never` 策略的原生辅助任务转发，会自动拒绝并显示通用的 `rejected by user`；这不意味着用户点击了拒绝。

本配置使用 Broker 正式支持的 `codexBin` 启动器入口，在真实 Codex 命令行添加 `-c windows.sandbox="unelevated"`。这只为 Broker 原本未启用沙箱的独立工作进程补上官方受限令牌沙箱；主 Codex 已有的 `elevated` 设置不变，`on-request`、每次调用的读写模式以及 Broker 审批保护都保留。

安装脚本位于 `assets/windows-broker`。它在个人 Codex 工具目录安装启动器，先备份已有内容和原始 Broker 配置，再仅更新顶层 `codexBin`，保留所有路线、模型、目录根及其他字段。启动器使用当前机器的 Node 和实际 Codex 可执行文件，不复制插件缓存，也不改用户 PATH。

进入新版配置包目录，在 PowerShell 7.2+ 运行：

```powershell
$bundleDir = (Get-Location).Path
$windowsInstaller = Join-Path $bundleDir 'assets\windows-broker\install-windows-broker.ps1'
pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass -File $windowsInstaller
if ($LASTEXITCODE -ne 0) { throw 'Windows 启动器安装未完成；处理固定错误后再继续。' }
```

默认安装到个人 `$CODEX_HOME/tools/mixagents-windows`，未设置 `CODEX_HOME` 时使用 `$env:USERPROFILE/.codex`。生成 `broker-codex.cmd`、`launch-broker-codex.mjs`、`settings.json`；备份放在该安装目录的 `backups` 子目录中，不放入分享包。默认 Broker 配置位置及 `MIXAGENTS_BROKER_CONFIG` 覆盖规则与第 4 节一致。

需要明确指定目标时，可使用 `-InstallDirectory`、`-BrokerConfigPath`、`-CodexExecutable`、`-NodeExecutable`，所有机器路径都应使用本机实际路径。例如自动发现失败时，先用 `Get-Command codex.exe` 和 `Get-Command node.exe` 核对后再显式传入；不要复制原机器带版本号的路径。若 Node 后续升级并删除了启动器记录的旧程序位置，重新执行安装脚本更新即可。

安装目录和实际 Codex 路径可以包含中文。为保证 `.cmd` 在不同系统代码页下可靠启动，记录在其中的 **Node 可执行文件路径须只含 ASCII，且不能含批处理特殊字符**（例如 `%`、`!`、`^`、`&`、括号）。若默认 Node 路径不满足条件，使用位于普通 ASCII 路径的本机 Node，通过 `-NodeExecutable` 指定；安装脚本会在修改配置前拒绝不支持的路径。路径中的普通空格可用。

**为何独立工作进程使用 unelevated：** OpenAI 推荐优先使用 elevated；但它的初始化状态与当前 Codex 配置目录绑定，在 Broker 新建的独立目录中启用可能触发 UAC、系统账户及防火墙设置。本方案使用无需该管理员初始化的官方 fallback，保留主机原有 elevated；不复制或链接 `.sandbox-secrets`，也不让 Broker 改用主 Codex 配置目录。两种模式的隔离能力不同，不能把 unelevated 描述成与 elevated 完全等价。

启用沙箱后，授权范围内的普通本地操作可直接在沙箱里执行；只读模式仍禁止写入，需要额外权限或外部行动的操作仍可能被拒绝。遇到拒绝应停止并报告，不能切换为完整访问或自动接受审批来解决。

修改 `codexBin` 后，已经缓存旧配置或已经运行的 Broker 进程不会自动更新，须按第 7.1 节完全重启。不要直接修改 Broker 生成的 `runtime/config.toml`，它会在下次启动被覆盖。

### 7.3 在两个目录的新任务中检查全局发现

在两个不同项目目录各建立一个新 Codex 任务，分别发送：

```text
只做安装检查：确认当前任务能发现 Broker、delegate-deepseek 和
```

预期：两处均能发现技能；路线为官方 DeepSeek，`available=true`，`maxAccess=workspace-write`。当前 Codex 版本的后端预期为 `app_server`。技能目录范围应是用户级；Broker 的技能可能显示为 `mixagents-broker:broker`。

### 7.4 可选：真实调用与文件命令验收

需要测试完整调用链时，用户明确发送下面这类指令才发起推理，会产生 DeepSeek API 用量：

```text
允许进行一次 DeepSeek 最小只读调用测试：在当前任务目录运行，
只回复 BROKER_READ_ONLY_OK，不读写文件、不调用工具或执行命令。
请主代理记录预检查 root 与实际 cwd 是否一致、agent ID、最终状态和回复。
```

2026-09-15 首先通过了上述无工具的最小调用，但随后发现普通文件读取仍被宿主自动拒绝；这说明固定回复不足以验证命令执行。补上第 6.5 节修复后，按用户授权，在新 Broker 连接中使用 `deepseek-flash` 完成了两项真实验收：

| 模式与独立测试目录 | 实际结果 |
| --- | --- |
| `read-only` / `ro` | 读取未放进提示词的随机 `input.txt`；返回内容与主代理读取的文件一致，1 次命令退出码为 0。 |
| `workspace-write` / `rw` | 读取输入并写入 `result.txt`，主代理确认内容一致；再执行 `12 * 12` 返回 144，3 次命令退出码均为 0。 |

两项均为 `completed`，实际 `cwd` 与各自预检查目录一致。会话记录确认保留 `on-request` 与对应读写模式，控制器未遇到审批或拒绝。验收既检查了磁盘文件，也核对了实际命令输出；未仅凭模型自述判定成功。可分享的摘要见 [validation/deepseek-live-results.json](validation/deepseek-live-results.json)，不包含本机路径、密钥或原始会话。

在其他机器验证时，可明确授权主代理新建两个小型测试目录和随机输入，再让 DeepSeek 分别执行上述只读、写入及本地计算，并由主代理独立检查输出。仅操作测试目录，首次出现拒绝就停止排查，不重复派发。

2026-09-12 的安装验证没有进行付费推理；本次按用户授权完成了真实 DeepSeek 验收，会产生 API 用量。离线脚本测试与真实 API 测试分别记录。只读写入被阻止另由不调用外部模型的隔离测试验证；本次未验证跨目录写入、联网或提权操作，也不代表其他实体机器已经通过。旧连接仍须重新加载，不能把新连接成功等同于所有旧任务已刷新。

## 9. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 `npm.cmd` | 安装完整 Node/npm，或使用第 2.3 节便携包；插件安装命令要在包含其路径的终端执行。 |
| 插件启动提示找不到 `node` | 确认启动 Codex 的环境能找到 Node；仅一次终端设置 PATH 不够。配置长期路径后完全重启。 |
| 找不到 `codex` 工作程序 | 先确认目标机器的真实可执行文件，再通过第 6.5 节安装脚本的 `-CodexExecutable` 更新启动器。已采用 Windows 修复时，`codexBin` 应指向专用启动器；检查是否存在覆盖它的 `MIXAGENTS_BROKER_CODEX_BIN`，不要直接改回未经配置的工作程序。 |
| 检查脚本成功，Broker 仍提示缺密钥 | 脚本读取用户环境，而旧 Broker 可能仍持有旧进程环境。完全重启 Codex及其启动终端；确认配置的是映射变量，而非仅裸密钥变量。 |
| `OWNER_BINDING_MISSING` / `OWNER_BINDING_INVALID` | 在目标 Windows 用户下重新执行第 5.2 节生成本机身份绑定，不复制旧机 SID。 |
| `OWNER_MISMATCH` | 脚本运行身份与凭据所属用户不同。用凭据所属用户运行检查；不要改查其他用户注册表或更改绑定来绕过核验。 |
| `CREDENTIALS_MISSING` / `CREDENTIALS_INVALID` | 用户环境映射不存在或格式不正确。在本机重新导入，保留其他提供商的映射，不把原内容贴到聊天。 |
| `AUTHENTICATION_FAILED` | 密钥无效、过期或无权限；在官方账户核对后本地重新输入。 |
| `RATE_LIMITED` / `NETWORK_ERROR` | 查看网络或官方限流情况，稍后重试；不要因此更换成不明中转地址。 |
| `REDIRECT_REJECTED` | 检查脚本拒绝转发携带凭据的请求；核对官方地址、网络代理和官方接口说明。 |
| 新目录无法使用 | 先按第 6.3 节检查实际子任务目录，必须早于首次 Broker 工具调用；已加载旧配置则正常重连或重启。 |
| `workspace_approval_declined`，几毫秒内失败 | 可能尚未取得启动目录授权；本机故障与桌面表单能力和 `never` 审批策略的兼容组合有关，并非密钥或模型故障。按下方修复顺序处理；用户真实拒绝或取消时停止。 |
| 预检查成功仍报相同错误 | `changed=false` 不代表连接刷新。检查规范化 `root` 与 `spawn.cwd`、配置覆盖路径和连接是否缓存；新状态未确认前不反复派发。 |
| `workspace_invalid_or_unavailable` / `workspace_too_broad` | 使用任务需要、已经授权且可访问的精确绝对目录；不要扩大到磁盘根或用户主目录。 |
| `existing_root_invalid_or_unavailable` | 检查已有根目录字符串格式；已删除或不可访问但格式有效的旧根会保留并跳过，不会单独触发此错误。 |
| `config_busy` / `config_changed_concurrently` | 有其他配置事务或检测到并发修改，保持现有文件；待修改结束后重新核对并执行，不用旧备份直接覆盖。 |
| 配置已允许写入，但调用仍只读或不能写另一个根 | 确认本次授权、`access=workspace-write` 及连接配置。`workspaceRoots` 只授权启动 cwd，不赋予其他登记根的写权限。 |
| 出现命令或文件权限确认 | 这是 Codex 宿主的运行时审批。主代理的任务范围授权不等同于代替所有宿主审批。 |
| 已能启动，但读取命令返回 `CreateProcess ... Rejected` | 检查第 6.5 节的 Windows 启动器是否安装、`codexBin` 是否指向它、连接是否已重建。缺少实际 Windows 沙箱时普通读取也会请求审批；外层辅助任务的 `never` 会自动拒绝该表单。停止重复执行；必要时由主代理提供已批准的文本材料或完成该部分，不关闭沙箱。 |
| PowerShell 报语法或版本错误 | 使用 PowerShell 7.2 或更新版本的 `pwsh`，推荐 7.4 或更新版本；Windows PowerShell 5.1 和 PowerShell 7.0/7.1 不满足配套脚本要求。 |
| 技能没有出现 | 检查 `CODEX_HOME` 是否与应用一致，是否复制了整个目录，是否新开任务；检查技能名和目录结构。 |

目录授权故障的处理顺序：先停止失败后的重复派发，核对实际 `cwd` 和当前配置路径；在已有用户授权内运行预检查；让新连接加载结果，再继续已批准的任务。只有具体修复或可核验的新状态解决原阻塞后才继续；用户明确拒绝或取消时不把全局目录偏好当作覆盖拒绝的授权。

本机对 `workspace_approval_declined` 的原因属于高置信度静态还原：当时没有客户端 roots，也未启用新版完整访问表单例外，审批策略为 `never`；未捕获失败当次的原始表单回复，因此不能仅凭这个错误码断言其他机器都出于同一原因。修复使用官方支持的目录配置，没有改变审批策略或插件程序。

## 10. 回退、复现记录与资料来源

卸载 Broker 插件：

```powershell
codex plugin remove mixagents-broker@mixagents
```

回退其他改动时，只处理本方案添加的内容：将两项个人技能移出有效技能目录，移除 AGENTS 中对应标记块，删除或恢复目标 Broker 路线，并按实际需要移除凭据过滤项。保留其他路线、插件和个人规则。配置备份用于比较或恢复对应改动，不要用旧整份配置覆盖安装后产生的新设置。

仅撤销本版目录修复时，对照脚本生成的 `broker.json.workspace-<时间与随机标识>.bak`，从最新 `workspaceRoots` 中仅移除本次新增的目录，保留其他目录和后续设置；用第 6.4 节备份恢复本次修改的委派规则与技能，再重新加载连接。不必删除密钥或更改模型。

撤销 Windows 启动器时，对照安装时备份，只恢复先前的 `codexBin` 值；原来没有该字段时只移除该字段，保留后续其他配置。让 Broker 重建连接后再移除不再使用的专用启动器。不要用旧整份配置覆盖后续的目录授权或模型切换。

若不再使用 DeepSeek，用户环境映射中只删除 `DEEPSEEK_API_KEY`；还有其他提供商时保留它们。不要把密钥、运行历史、整个 `.codex` 目录或配置备份加入分享包。

初次安装验证包括插件和路线解析、两个目录的新进程技能发现、凭据与模型列表、权限默认值、技能格式及模型切换模拟测试。本版新增目录预检查脚本及其隔离测试，并将本机实际修复后的个人委派规则同步到便携资产；原模型检查技能的便携实现保留。脚本测试、资产哈希和文档检查见 `validation`；本次真实调用的范围与限制见第 7.4 节。目标机器仍应完成第 7 节验证。
